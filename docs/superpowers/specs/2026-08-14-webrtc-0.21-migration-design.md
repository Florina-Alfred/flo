# Migrate media feature to webrtc 0.21 (Sans-I/O)

Date: 2026-08-14
Status: Approved (design review)

## Problem

The optional `media` feature of `flo-rs` builds on `webrtc 0.17`. Upstream's
`webrtc 0.21` line (currently only published as `0.21.0-alpha.1`) is a complete
Sans-I/O API rewrite; the 0.17 API surface flo uses is gone. The default build is
unaffected — `media` is optional — but the media feature is currently pinned on an
obsolete major. This design migrates flo's media feature onto `webrtc 0.21`,
**behavior-preserving**: single H.264 outbound track per peer, host-candidate-only
ICE, trickle ICE via the existing zenoh signaling plane, receive path a no-op.

Deferred issue #161 tracked this; it is now being addressed. This is a
behavior-preserving migration, not a feature addition (no STUN/TURN config surface,
no receive rendering).

## Scope

- Only `src/video.rs` and `src/codec.rs` touch webrtc (verified by inventory).
- `src/signaling.rs` wire format is webrtc-type-free and is **not** changed.
- `src/media.rs` (GStreamer capture/encode) is **not** changed.
- `src/mesh.rs`, `common.rs`, `transport.rs` depend on `VideoPeer`'s public API,
  which is preserved.

## Decisions

### Dependencies (approved by admin)

| Change | Rationale |
|---|---|
| `webrtc` `0.17.1` → `0.21.0-alpha.1` | Only 0.21 published; default features `runtime-tokio` + `crypto-ring` match flo's tokio runtime. |
| **Add** `rtc = "0.21.0-alpha.1"` | The `webrtc` facade does not re-export the construction types flo must name (`RTCRtpCodecParameters`, `RTCRtpCodec`, `RTCRtpEncodingParameters`, `RTCRtpCodingParameters`, `RtpCodecKind`, `SSRC`, `PayloadType`, `Sample`, `MIME_TYPE_H264`). Upstream examples import these from `rtc` directly. Same version as `webrtc`; already resolved transitively. |
| **Add** `async-trait = "0.1"` | Required to `impl PeerConnectionEventHandler`. Not re-exported by `webrtc`. |
| **Drop** `gstreamer-video` | Declared + locked but never imported anywhere (verified). Dormant feature-gated dep; zero behavior change. |

Alpha status of `webrtc 0.21.0-alpha.1` is an accepted, documented risk (this spec
+ CHANGELOG `[Unreleased]` note). Track upstream for a stable 0.21 and re-evaluate.

### Scope guardrails

- Preserve current behavior exactly (single H.264 send track, host-only ICE, trickle
  ICE, receive no-op). No new config surface, no STUN/TURN.
- Signaling wire format (`SignalMessage` / `IceCandidate`) unchanged.
- No new tests beyond adapting the existing three webrtc-touching tests.

## Design

### `src/codec.rs`

Replace `h264_codec_capability() -> RTCRtpCodecCapability` with

```rust
pub fn h264_codec_parameters() -> rtc::rtp_transceiver::rtp_sender::RTCRtpCodecParameters
```

Same fields as today (`MIME_TYPE_H264`, `clock_rate: 90_000`, `channels: 0`,
`sdp_fmtp_line: "level-asymmetry-allowed=1;packetization-mode=1"`,
`rtcp_feedback: vec![]`) plus `payload_type: 102` (the value hardcoded in
`video.rs:55` today). The inner `RTCRtpCodec` is reused both for
`MediaEngine::register_codec` and for the track's coding.

### `src/video.rs`

**`h264_track(id: String, stream_id: String) -> Arc<TrackLocalStaticSample>`** —
signature preserved (callers pass `format!("{robot_id}-cam0")` /
`format!("{robot_id}-stream0")`); only the internals change. Builds a
`MediaStreamTrack` (stream id `stream_id`, track id `id`, label, `RtpCodecKind::Video`,
one encoding with `ssrc` + the codec) and wraps it in
`TrackLocalStaticSample::new(Instant::now(), track)`.

**`VideoPeer` fields**:
- `pc: Arc<dyn PeerConnection>` (was concrete `Arc<RTCPeerConnection>`)
- `track: Arc<TrackLocalStaticSample>`
- `sender: Arc<dyn RtpSender>` (new — resolve negotiated payload type)
- `transport: Arc<Transport>` (unchanged)

**`VideoHandler`** — new private struct implementing `PeerConnectionEventHandler`
(replaces the 0.17 closure callbacks):
- `on_ice_candidate`: `event.candidate.to_json()` → `RTCIceCandidateInit` →
  project `candidate`/`sdp_mid`/`sdp_mline_index` into `signaling::IceCandidate` →
  `signaling::publish_ice`. Same wire payload as today.
- `on_track`: log only (receive no-op).
- `on_connection_state_change`: log.

**PC construction** (in the `offer`/`answer` paths, replacing `build()`):

```rust
let mut media_engine = MediaEngine::default();
media_engine.register_codec(h264_codec_parameters(), RtpCodecKind::Video)?;
let config = RTCConfigurationBuilder::new().build();   // no ICE servers
let pc: Arc<dyn PeerConnection> = Arc::new(
    PeerConnectionBuilder::new()
        .with_configuration(config)
        .with_media_engine(media_engine)
        .with_handler(Arc::new(VideoHandler { transport, robot_id, peer_id }))
        .with_udp_addrs(vec!["0.0.0.0:0"])
        .build().await?,
);
let sender = pc.add_track(track.clone()).await?;
```

**`SignalHandler` impl** — near 1:1 with today:
- `on_answer`: `RTCSessionDescription::answer(msg.sdp.clone())?` →
  `set_remote_description(desc).await`
- `on_offer`: `RTCSessionDescription::offer(..)` → `set_remote_description` →
  `create_answer(None)` → `set_local_description` → `publish_answer`
- `on_ice`: build `RTCIceCandidateInit { candidate, sdp_mid, sdp_mline_index,
  username_fragment: None, url: None }` → `pc.add_ice_candidate(init).await`
- `offer()`: `create_offer(None)` → `set_local_description(offer.clone())` →
  `publish_offer(offer.sdp, vec![])`

### Sample path (`start_capture`)

- GStreamer side untouched.
- Resolve once after `add_track`:
  - `ssrc = *track.ssrcs().await.first().unwrap()`
  - `payload_type = sender.get_parameters().await?.rtp_parameters.codecs.first().unwrap().payload_type`
    (mirrors upstream `negotiated_payload_type` helper)
- Per frame:

```rust
let sample = Sample {
    data: Bytes::copy_from_slice(bytes),
    duration: Duration::from_secs_f64(1.0 / fps),
    ..Sample::new(Instant::now())
};
track.sample_writer(ssrc, payload_type).write_sample(&sample).await?;
```

- Drop the manual 90 kHz `packet_timestamp` counter (`ticks_per_frame`/`AtomicU32`);
  0.21's packetizer derives RTP timestamps from `sample.duration`.
- `Sample.timestamp` is `Instant` (was `SystemTime`). No observable wire change.
- SSRC source: deterministic counter-based value (e.g. an `AtomicU32`), not `rand` —
  avoids a third new dependency. Uniqueness per peer is what matters; any value works.

### Tests (media-gated, adapted to the new API)

- `h264_track_has_correct_codec`: `let ssrc = *t.ssrcs().await.first().unwrap(); let
  codec = t.codec(ssrc).await.unwrap();` then assert `codec.mime_type ==
  MIME_TYPE_H264` and `clock_rate == 90_000`. `MIME_TYPE_H264` now from
  `rtc::peer_connection::configuration::media_engine`.
- `answerer_can_start_capture`: `track().track_id().await` replaces `track().id()`;
  `start_capture` unchanged.
- `mesh_handler_answers_inbound_offer` (mesh.rs): unchanged API; exercises the real
  offer→answer handshake on loopback.

## Verification

- `cargo check --features media`
- `cargo test --features media` (the three webrtc tests + GStreamer pipeline tests)
- `cargo clippy --features media` with `-D warnings`
- `cargo fmt`
- Default build (`cargo check`) must stay green (media is optional).

## Risks

- **Alpha crate**: `webrtc 0.21.0-alpha.1` — API may shift before stable. Mitigated
  by pinning exact version in `Cargo.toml` (not `^`) and tracking upstream. Revisit
  when a stable 0.21 lands.
- **Two new direct deps** (`rtc`, `async-trait`) — admin-approved; same version as
  the pinned `webrtc`, already in the lockfile transitively.
- Loopback handshake test depends on `with_udp_addrs` binding — expected fine on
  `0.0.0.0:0`.

## Out of scope

- webrtc 0.20 (superseded by 0.21).
- STUN/TURN / ICE-server config surface.
- Receive-side media rendering.
- `--video-self-test` (dead flag today; unrelated).
